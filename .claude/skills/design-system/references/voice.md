# Tone of voice

Five attributes. Each has a one-line rule and a Good/Bad pair. Use them on every page, heading, and CTA.

## 1. Engineering-credible
Rule: name real technologies and patterns precisely; write as engineers, for engineers.
- Good: "Multi-cluster OpenShift, defined as code — GitOps with Argo CD app-of-apps and sync-wave ordering."
- Bad: "Best-in-class cloud-native solutions powered by industry-leading technology."

## 2. Confident, not hype
Rule: state what we do plainly; no superlatives, no buzzword stacking.
- Good: "We turn OpenShift GitOps into autonomous operations."
- Bad: "We leverage world-class, cutting-edge cloud synergies."

## 3. Concise
Rule: active voice, outcome first, cut filler — short sentences over padded ones.
- Good: "Fewer pages. Faster recovery. A signed audit trail on every change."
- Bad: "Our solution is designed to potentially help reduce the number of incidents that may require human attention over time."

## 4. Honest
Rule: claim only delivered capability; anonymize; never invent a metric or imply OpenShift where it was AKS.
- Good: "A Fortune-500 retailer — AIOps automation depth (a Kubernetes engagement, not an OpenShift reference)."
- Bad: "Acme Retail trusts our OpenShift platform — 99.99% uptime, 80% fewer incidents." (names a client, fakes metrics, and the work was AKS not OpenShift)

## 5. Human + machine
Rule: agents do the routine work; humans set intent and own the guardrails — say so.
- Good: "Humans set intent and own the guardrails; agents detect, plan, act and verify."
- Bad: "Fully autonomous AI runs your entire platform with zero human involvement."
